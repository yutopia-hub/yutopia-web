# 요구사항 (RFP) — 관통프로젝트 공식 자료 정리

삼성청년SW·AI아카데미 Frontend 관통프로젝트 자료 기준으로 정리. 빠진 부분은 "자료에 없음"으로 명시.

파일명은 한글 경로 깨짐 방지를 위해 영문(`REQUIREMENTS_RFP.md`)으로 작성, 본문은 기존 문서들과 통일해서 한글로 유지.

## 요약 표

| 우선순위 | 영역               | 핵심 요구사항                                           | 비고                                        |
| -------- | ------------------ | ------------------------------------------------------- | ------------------------------------------- |
| 상       | FrontEnd 관통      | HTML/CSS/순수 JS로 프론트엔드 구현                      | 프레임워크 사용 여부는 자료에 명시 없음     |
| 상       | Map 활용           | 카카오맵 API로 지도 표시, 마커, 주소 ↔ 좌표 변환        | appkey 관리 방식 포함                       |
| 상       | 공공 API 활용      | 한국관광공사 TourAPI 연동 (AJAX/Fetch)                  | CORS 이슈 처리 또는 로컬 데이터 폴백 고려   |
| 상       | AI 페어 프로그래밍 | R&R 명확화, 단계별 AI 활용, 커밋에 AI 활용 내역 기록    | 핵심 평가 포인트로 보임                     |
| 중       | 이미지/저작권      | 공공API 이미지 라이선스 유형 확인, CI/BI 무단 사용 금지 | 기능이 아닌 준수사항, 위반 시 감점 리스크   |
| 하       | 빌드 도구 / 배포   | **자료에 명시 없음**                                    | 이 프로젝트는 Vite로 임의 선택, 배포는 미정 |

우선순위 기준: **상** = 자료에 명시된 필수 과제 영역 / 핵심 평가 포인트, **중** = 필수는 아니지만 위반 시 리스크 있는 준수사항, **하** = 자료에 지정 없이 자유롭게 정한 영역.

## 1. Map 활용 (카카오맵)

- Kakao 지도 Web API 사용. 로드 스크립트: `//dapi.kakao.com/v2/maps/sdk.js?appkey=...`
- 사용 가능 라이브러리:
  - `clusterer` — 마커 클러스터링
  - `services` — 주소 ↔ 좌표 변환 등
  - `drawing` — 그래픽 객체 그리기
- appkey는 하드코딩하지 않고 변수로 관리, 페이지마다 script 태그를 중복 삽입하지 않도록 동적 로딩 헬퍼 권장 (예: `loadKakaoMap()` 패턴, `keys.js`에서 `KAKAO_MAP_KEY` export).
- 주소 → 좌표 변환: `kakao.maps.services.Geocoder().addressSearch(addr, callback)` (비동기, 콜백 기반). 성공 여부는 `kakao.maps.services.Status.OK`로 체크.
- 마커 여러 개 표시 패턴: 기존 마커 배열 유지 → 지우기 → 새로 생성 → `LatLngBounds`로 전체 마커가 화면에 들어오게 지도 범위 자동 조정 (`extend()` + `map.setBounds(bounds)`).
- 좌표가 한국 영역인지 체크하는 예시 범위: 위도 33.0~38.6, 경도 124.5~132.

## 2. 공공 API 활용

- 프론트에서 AJAX/Fetch로 공공 API를 직접 호출하는 구조. 자료의 다이어그램에는 두 가지 경로가 모두 있음:
  1. Back-End를 거쳐 공공 API 호출
  2. Front에서 Fetch API로 직접 호출 (CORS 이슈 발생 가능 → 처리 필요) + 로컬 xml/json 폴백
- 명시된 공공데이터 소스: **한국관광공사 TourAPI (국문 관광정보 서비스_GW)**
  - 목록/검색: `areaBasedList2`, `locationBasedList2`, `searchKeyword2`, `searchFestival2`, `searchStay2`
  - 상세: `detailCommon2`, `detailIntro2`, `detailInfo2`, `detailImage2`
  - 테마: `detailPetTour2` (반려동물 동반여행)
  - 기초코드: `lclsSystmCode2`, `ldongCode2`

## 3. 이미지 / 저작권 주의사항

- 공공API에서 제공하는 사진(이미지)은 **1유형(출처표시) 또는 3유형(출처표시+가공금지)** 라이선스가 적용된 것만 사용.
- 이미지 속 피사체(인물 등)의 명예훼손/인격권 침해 소지가 있는 매체는 사용 금지.
- 기업 CI/BI 무단 활용은 절대 금지.

## 4. AI 페어 프로그래밍 가이드

이 과제의 핵심 평가 포인트로 보이는 부분. "AI 페어 프로그래머"가 되는 게 목표이며, AI가 코드를 더 많이 작성하게 될수록 사람에게 남는 핵심 역량(문제 이해, 기준 수립, 결과 검증 능력)이 중요해진다는 전제.

- 팀원의 R&R(role & responsibility)을 명확히 하고, 작업 전 AI에게 시스템 프롬프트를 지정하는 걸 권장.
  - 예시: _"너는 우리 여행 웹 프론트엔드 멘토야. 우리는 HTML, CSS, 순수 JavaScript만 사용하고 있어. 내가 질문을 하면 바로 동작하는 코드를 던져주지 말고, 어떤 원리로 동작하는지 설명하거나 필요한 브라우저 API 이름과 수도코드 형태로만 힌트를 제공해줘. 정답 코드를 통째로 작성해주지 마라."_
- 단계별 AI 활용 역할:
  - **기획 & 요구사항 명세** — 비즈니스 분석가 역할. 모호한 아이디어를 구체적인 User Story 단위로 구체화 요청.
  - **설계 & 더미데이터 생성** — DB 엔지니어/백엔드 역할. 더미 데이터를 JSON으로 대량 생성 요청.
  - **구현** — 코드 리뷰어 역할. "왜 이 CSS 속성을 썼는지", "왜 이 오류가 발생했는지", "리팩토링 포인트 3가지만" 등 설명 요청형 질문 위주로 활용.
- **커밋 메시지/PR에 AI 활용 내역 기록 권장**: 문제 정의(AI에게 뭘 물어봤는지) / 학습한 점(AI가 제안한 핵심 원리) / 본인 기여(그 제안을 어떻게 변형·적용했는지) 3가지.

## 5. 빌드 도구 / 배포

자료 전체(26장)를 확인했지만 **번들러(Vite 등) 사용 여부, 배포 방식(호스팅 플랫폼, 배포 명령 등)에 대한 언급이 전혀 없음**. 순수 HTML/CSS/JS, AJAX(Fetch API) 활용만 명시되어 있음.

- 이 프로젝트는 자유롭게 선택 가능한 영역으로 보고 **Vite**를 빌드 도구로 선택함 ([AGENT.md](../AGENT.md) 참고).
- 배포 방식은 아직 미정 (추후 결정).
